## 1. 원래 업무 질문

### 내가 선택한 막연한 질문

```text
여기에 작성하세요.
매출을 높이기 위해 어떤 상품 카테고리의 취급을 확대하고, 어떤 카테고리의 취급을 축소해야 할까?
```

### 왜 이 질문이 모호하다고 생각했는가?

- 대상:어떤 상품 카테고리를 뜻하는지는 알 수 있지만, 판매 금액·판매 수량·주문 수 중 무엇을 기준으로 볼지 정해지지 않았다.
- 기간:어느 기간의 주문을 비교할지 정해지지 않았다.
- 기준:completed 주문만 포함할지, 취소 주문도 고려할지 정해지지 않았다.
- 비교 방법:카테고리별 절대 금액을 비교할지, 기간별 변화까지 비교할지 정해지지 않았다.또한 추세나 예측치를 얼마나 반영할지도 생각하지 않았다.
- 분석 목적:취급 확대·축소라는 의사결정은 명확하지만, 원가·마진·재고 정보 없이 판매 성과만으로 최종 결정을 내릴 수 있는지는 불분명하다.

### 분석 가능한 질문으로 다시 작성

```text
제공된 주문 기간의 completed 주문을 기준으로,
상품 카테고리별 판매 금액, 판매 수량, 주문 건수는 어떠하며
상대적으로 낮은 판매 성과를 보이는 카테고리는 무엇인가?
```

### 결과 관찰

막연했던 취급 확대·축소 질문을 completed 주문, 카테고리, 판매 금액·수량·주문 건수라는 구체적인 기준으로 바꾸었다. 따라서 어떤 데이터를 사용하고 무엇을 비교할지 명확해졌다.

### 나의 해석과 판단

현재 제공된 주문·상품·주문상세 데이터로 직접 확인할 수 있는 판매 성과를 중심으로 질문을 바꾸었기 때문에 실제 분석에 더 적합하다고 판단했다.

### 업무·분석적 의미

카테고리별 판매 성과를 비교하면 취급 확대 또는 축소를 검토할 후보를 찾고, 이후 상품 구성이나 판매 전략을 점검하는 데 도움이 될 수 있다.

### 한계와 추가 확인 사항

판매 성과가 낮다고 바로 취급을 축소할 수는 없다. 원가, 이익률, 재고, 공급 계약, 계절성 정보가 없으므로 최종 의사결정 전에는 추가 확인이 필요하다.

| `order_items.csv` | `order_id`, `product_id`, `quantity`, `unit_price` | 주문별 상품을 연결하고 판매 수량과 판매 금액을 계산하기 위해 필요하다. |
| `products.csv` | `product_id`, `category` | 상품별 주문상세를 카테고리별로 묶기 위해 필요하다. |

products.product_id
        ↓

수량과 단가가 있는 order_items.csv, 카테고리 정보가 있는 products.csv가 필요했다.
customers.csv는 현재 질문에 필수는 아니었다.

### 나의 해석과 판단

현재 데이터로 카테고리별 판매 금액, 판매 수량, 주문 건수는 계산할 수 있다고 판단했다.
다만 세 파일을 order_id와 product_id로 정확히 연결해야 한다.

### 업무·분석적 의미

분석 질문을 실제 파일과 컬럼으로 연결하면, 현재 데이터로 가능한 분석과
추가 정보가 필요한 분석을 구분할 수 있다.

### 한계와 추가 확인 사항

컬럼 이름은 확인했지만, 결측치·중복·환불 처리·할인 반영 여부와
unit_price가 실제 판매 단가를 정확히 의미하는지는 추가 확인이 필요하다.

LLM은 분석 질문의 초안을 빠르게 제안할 수 있지만, 실제 데이터 구조와 계산 기준을 보장하지는 않는다.
따라서 분석 전에 질문을 필요한 파일, 컬럼, 연결 관계로 바꾸어 확인해야 한다.
관찰된 판매 성과의 차이와 그 원인을 구분해서 해석하는 것도 중요하다.
최종적으로 어떤 분석을 사용할지는 사람이 책임지고 판단해야 한다.

### LLM을 데이터 분석에 사용할 때 가장 조심해야 할 점

```text
자신의 판단을 작성하세요.
```
LLM이 자연스럽게 설명한 내용을 사실이나 원인으로 바로 받아들이지 않는 것이 가장 중요하다고 생각한다.
실제 컬럼 존재 여부, 계산 범위, 데이터 품질을 확인하지 않으면 그럴듯하지만 잘못된 분석이 될 수 있다.
또한 API key등 개인정보를 github나 online llm에 업로드하는 것을 조심해야 한다고 생각하였다. 
### 사람과 LLM의 역할 차이

| 항목 | LLM이 도울 수 있는 부분 | 사람이 책임져야 하는 부분 |
| --- | --- | --- |
| 질문 정의 | 분석 질문 후보 제안 | 분석 목적과 범위 결정 |
| 데이터 확인 | 필요한 파일·컬럼 후보 제시 | 실제 데이터 구조와 품질 검증 |
| 코드 작성 | 코드 초안과 설명 제공 | 실행, 오류 수정, 결과 검증 |
| 결과 해석 | 해석 관점 제안 | 원인 단정 방지와 업무 판단 |
| 최종 판단 | 선택지 정리 | 채택 여부와 책임 |
